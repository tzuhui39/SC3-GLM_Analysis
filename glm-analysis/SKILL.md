# 廣義線性模型（GLM）分析 skill

## 核心工作流程（完整分析模式的四個階段）

1. **探索性資料分析（EDA）**
2. **適合性評估**：這筆資料適不適合用 GLM？該用哪個分佈家族／連結函數？
3. **模型配適**：實際 `glm()` 配適，解釋係數
4. **模型診斷與評估**：檢查先前的假設與模型是否站得住腳

**所有階段開始之前**，先列出資料的全部變數；若使用者沒有說明哪個是反應變數（Y）、哪些是解釋變數（X），必須先用選擇題詢問使用者並等到回覆，才能開始 EDA（細節見 Stage 1-0）。EDA 做完後，還要請使用者確認資料有沒有 typo 或奇怪的數值（尤其最大最小值），使用者確認沒問題才能進入 Stage 2（細節見 Stage 1-2）。

### 三種工作模式

先判斷使用者要的是哪一種，不要一律強迫從頭走完：

- **完整分析模式**：使用者給資料、要求做 GLM 分析或迴歸分析時，依序完成 Stage 1 到 4。四個階段都要在回覆中清楚分節、逐步說明「在做什麼、為什麼這樣做、結果代表什麼意思」，不省略步驟、不直接跳到結論。「不可跳步驟」只適用於這個模式。
- **指定步驟模式**：使用者只問某項診斷、某個係數的解釋、某個概念，或只要 EDA 時，直接處理該問題並完整解釋，不必重跑所有階段，也不必重新列變數、重新等待確認。
- **延續既有分析模式**：對話中前面的 EDA、模型配適已經完成，且資料與模型沒有改變時，直接接續，不重複要求使用者確認相同的內容。資料或模型一有變動（換變數、換模型、處理資料），就要重新做受影響部分的檢查。

### 語言與用詞

- **預設使用台灣繁體中文回應**（對話、勾選框、報告檔案皆同），使用者改用其他語言時才跟著改。
- **專有名詞第一次出現時附註英文**，例如「連結函數（link function）」「過度離散（overdispersion）」「概似比檢定（likelihood ratio test, LRT）」「變異數膨脹因子（variance inflation factor, VIF）」「勝算比（odds ratio）」。同一份回覆或報告中，之後可只用中文或常見縮寫。
- R 函式、套件、參數名稱（`glm()`、`emmeans`、`family`）維持原文，不翻譯。
- 統計量與模型名稱沿用慣用寫法，例如 AIC、BIC、Poisson、Gamma、θ，不強迫翻成中文。

### 向使用者提問的方式（所有需要使用者選擇的地方都適用）

需要使用者做選擇時，**一律用 `AskUserQuestion` 的選項（勾選框）提問**，不要用純文字提問後結束這一輪回覆，因為純文字提問會讓使用者誤以為分析已經結束。

- 每次呼叫最多 4 個問題、每題 2 到 4 個選項（使用者永遠可以選「其他」自行輸入）。先把這一階段所有要問的問題**集中在同一次呼叫**，不要問一題、等一題。
- 選項要具體：變數很多時，用「建議排除」「建議納入」分組當選項，或用多選題讓使用者勾選要排除的變數；建議用 `(Recommended)` 標在第一個選項。
- 只有環境完全沒有 `AskUserQuestion` 時，才退回純文字提問，而且要在文字中明講「分析尚未開始，正在等您回覆」。
- 問題只問使用者才知道的事（Y 是什麼、哪些變數不放入、變數的時間順序、資料是否有誤、輸出形式），能從資料或前面的回覆判斷的不要問。

### 統計判斷與自動化決策原則（所有階段共同遵守）

診斷指標是證據，不是自動決策規則。

1. 不得僅憑單一圖形、檢定 p 值或經驗門檻，自動宣告模型正確、錯誤或必須更換。
2. 每項診斷結果都必須結合資料結構、研究目的、模型假設及其他診斷證據解釋。
3. 發現問題時，先辨識可能原因，再提出適當的處理選項；不得將所有問題一律歸因於同一個模型假設。
4. 更換 family、link、函數形式或變數組合後，應重新配適模型，並重新執行相關診斷，不能假設單一修改已解決所有問題。
5. 若有多個合理模型，應說明各模型的優缺點、選模依據與限制；不得只因某模型的 p 值較小、AIC 較低或係數較容易解釋，就宣稱它是唯一正確的模型。
6. 最終結論必須與最終模型、研究目的及資料實際支持的證據一致；若證據不足，應明確說明不確定性，而不是強行產生確定結論。

### 結果與結論撰寫原則（所有階段、對話與報告都適用）

1. **簡潔扼要**：先說重點，再說必要的數據與解釋。避免冗長、重複或難以理解的敘述。
2. **中立客觀**：依據實際分析結果下結論，不迎合預期，也不刻意誇大或淡化結果。
3. **不可無據推論**：沒有證據支持的原因、機制或結論，不得當成事實。推測必須明確標示為可能的解釋。
4. **正確表達不確定性**：未達統計顯著不代表沒有關聯；未發現問題不代表證明沒有問題。
5. **結論必須有依據**：不得編造數據、檢定結果或文獻。證據不足時，直接說明「目前資料不足以判斷」。
6. **避免過度解釋**：只解釋分析結果能支持的內容，不自行延伸因果關係或未經驗證的原因。
7. **用白話說明**：優先使用清楚、直接的語句，必要時才補充統計術語。

**輸出前檢查**：結論是否正確、有證據支持、沒有過度推論，且能用最少的文字清楚表達重點。

**引用文獻**：說明方法依據或在報告中列參考文獻時，先讀 `references/literature.md`，只引用其中、且該次分析實際用到的方法的文獻；清單沒有的文獻不得自行產生，作者、年份、卷期頁碼、DOI 一律照清單，不憑記憶補寫。產出 Quarto 報告時，把 `assets/references.bib` 複製到報告 qmd 的同一資料夾（範本 YAML 已設定 `bibliography: references.bib`），在內文的方法說明處用 `[@key]` 引用（鍵值見 `literature.md` 每筆後面），範本最後的「參考文獻」節會自動只列出有引用的文獻；交付報告時 `.bib` 要和 `.qmd` 一起附上。版本會變動的 R 套件，用 `toBibtex(citation("套件名"))` 實際取得後加進報告資料夾的 `.bib`，不自行撰寫。

**描述圖形前必須先看圖（硬性規定）**：寫模型診斷，或對任何圖（EDA 圖、殘差圖、Q-Q 圖、分組趨勢圖、報告轉出後的圖）做描述或下結論之前，**必須先把圖存成圖片檔，並用 Read 等工具實際查看圖的內容**，再依看到的內容描述。不可以憑感覺、印象、圖形類型的一般樣貌或程式碼的預期結果就下結論（例如沒看圖就寫「殘差大致隨機分布」「Q-Q 圖落在對角線上」）。看不到圖（例如環境無法存圖或讀圖），就明說「無法檢視圖形」，不要對圖下結論，改以數值診斷為主。圖看過之後，描述要具體（例如指出哪個區域、哪幾個點），並避免過度解讀。

### 何時暫停並與使用者討論

如果某個階段發現資料可能不適合直接套用 GLM（例如樣本數或事件數偏少、反應變數不屬於常見 GLM 家族、觀測值相依、模型無法識別），要在該階段停下來明確告知使用者問題所在，說明對估計、解釋或預測的影響，提出選項（換模型、資料轉換、蒐集更多資料、改用本 skill 不支援的方法等），用勾選框詢問要不要繼續。

共線性、樣本數偏少這類問題**通常不是停止分析的充分理由**：若共線性使特定係數無法穩定估計、模型無法識別，或使研究問題無法回答，才暫停該項推論並與使用者討論；若仍能合理配適，可以繼續分析，但必須說明它對估計、解釋或預測的影響。

## 環境設置（每次新對話 session 開始時，先做這件事）

不要假設環境已經有 R 或特定套件，也不要假設一定有某個工具或輸出路徑。每次進行分析前，先確認實際可用的 R 執行方式（例如能在 shell 執行 `Rscript`）與所需套件。若沒有 R 環境、或無法安裝，要明確告知使用者這個限制，**不要假裝已經執行了分析**，也不要編造輸出。以下以常見的 Linux 容器為例（容器可能在對話之間重置）：

```bash
which Rscript
```

如果沒有輸出（代表沒裝），先確認是否有權限安裝、安裝來源是否可用，再安裝 R 與本 skill 需要的核心套件（在測試過的容器中，apt 來源可正常安裝，不需要 CRAN 鏡像）：

```bash
apt-get install -y --no-install-recommends \
  r-base-core r-cran-mass r-cran-car r-cran-ggplot2 \
  r-cran-dplyr r-cran-performance r-cran-knitr r-cran-rmarkdown r-cran-broom \
  r-cran-emmeans
```

這會裝好：
- `MASS`：`glm.nb()` 負二項迴歸、`boxcox()`
- `car`：`vif()` 共線性、`Anova()`
- `ggplot2`：繪圖
- `dplyr`：資料整理
- `performance`：`check_overdispersion()`、`check_collinearity()`、`check_model()`、`r2()` 等一站式診斷
- `knitr`：`kable()` 出表格、產報告用
- `rmarkdown`：Quarto 執行 R 程式區塊時需要
- `broom`：`tidy()` / `glance()` 把模型結果整理成資料框
- `emmeans`：類別變數的兩兩比較與多重比較校正（結論涉及「最好」「排名」或非參照組之間的比較時必用）

選用：`r-cran-dharma`（DHARMa 模擬殘差，作為較獨立的診斷補充）。裝不到就略過，並如實說沒有做這項檢查。

**只有要產出報告檔案時**才需要再裝 Quarto（pip 可以裝，已實測）：

```bash
pip install quarto-cli --break-system-packages
```

要輸出 PDF 時另外需要 LaTeX 與中文套件（已實測，缺少會出現 `lmodern.sty`、`xeCJK.sty not found`）：

```bash
apt-get install -y --no-install-recommends lmodern texlive-xetex \
  texlive-latex-recommended texlive-latex-extra texlive-fonts-recommended \
  texlive-lang-chinese texlive-lang-cjk fonts-noto-cjk
```

裝好之後用 `Rscript -e 'library(套件名)'` 快速確認沒有報錯即可繼續。實際分析一律用目前環境可用的 R 執行工具實際執行（例如在 shell 執行 `Rscript your_script.R`，或用 heredoc 寫檔後執行），把**真正的輸出**（模型摘要、檢定結果、圖檔）呈現給使用者，不要用記憶中的假輸出唬弄使用者。

**已知的環境陷阱（在測試過的容器中確認過）**：這個容器預設 locale 是 `POSIX`／`C`，不支援多位元組字元。如果 R 程式碼裡有中文（例如中文欄位名稱、`data.frame(中文欄位 = ...)`），會直接 parse error（`unexpected '<'` 之類的錯誤）。解法：**執行 `Rscript` 時一律在前面加上 `LC_ALL=C.UTF-8`**，例如：

```bash
LC_ALL=C.UTF-8 Rscript your_script.R
LC_ALL=C.UTF-8 quarto render report.qmd --to pdf
```

不要漏掉這個環境變數，否則只要程式碼或資料裡出現中文就會整段失敗。

另外，`performance::check_model(model)` 的畫圖功能需要額外的 `see` 套件，這個套件在此環境不一定能透過 apt 裝到。**預設請改用 base R 內建的 `plot(model)`（四合一診斷圖：Residuals vs Fitted、Normal Q-Q、Scale-Location、Residuals vs Leverage）當作總覽圖**，`check_overdispersion()`、`vif()` 等純文字輸出的診斷函式不受影響可正常使用。

## R 程式碼撰寫規範（硬性規定，務必遵守）

1. **絕對不要用 `---` 當作視覺分隔線**（不管是在 R 程式碼註解、對話文字、章節之間都不行）。唯一例外：Quarto（qmd）檔案最上方的 YAML frontmatter 語法上「必須」用 `---` 包住（例如 `--- \n title: ... \n ---`），這是 qmd 檔案格式的硬性語法，不算違反規則；但除了那個 YAML 區塊之外，檔案內文完全不要再出現 `---`。要分段就用中文標題（`##`、`###`）或空行分隔，不要畫線。
2. **絕對不要使用 `kableExtra::kable_styling()`**。表格一律用 `knitr::kable()` 本身輸出就好（在對話中可直接 `print()` 或用 `kable(x)`），不要再疊加 `kable_styling()` 或其他 kableExtra 的樣式函式。若使用者要求要更漂亮的表格排版，改用 `knitr::kable(..., format = "pipe")` 或直接呈現整理過的資料框，不要用 `kable_styling()`。
3. 程式碼中文註解要寫清楚每一步在做什麼。程式碼只出現在背景執行與報告檔案（qmd）中；在對話回覆裡不要貼 R 程式碼，使用者明確要求時才提供。
4. 圖表用 `ggplot2`，存成 `.png` 後用環境提供的圖片檢視或檔案傳送功能展示給使用者看，不要只描述圖長怎樣。

## Stage 1：探索性資料分析（EDA）

拿到資料後，**第一件事永遠是列出資料中的所有變數**，並確認哪個是反應變數（Y）、哪些是解釋變數（X），確認完才往下做。

### Stage 1-0：列出所有變數，確認 X / Y 與時間順序（必做，在任何分析之前）

1. 讀入資料後，先列出全部變數，用表格呈現（`knitr::kable()`，不要用 `kable_styling()`），至少包含：變數名稱、資料型態（numeric / integer / factor / character / logical）、不重複值個數、遺漏值個數、前幾個範例值。可用下面的寫法：

```r
var_tbl <- data.frame(
  變數名稱 = names(dat),
  資料型態 = sapply(dat, function(x) class(x)[1]),
  相異值個數 = sapply(dat, function(x) length(unique(x))),
  遺漏值個數 = sapply(dat, function(x) sum(is.na(x))),
  範例值 = sapply(dat, function(x) paste(head(unique(x), 3), collapse = ", ")),
  row.names = NULL
)
knitr::kable(var_tbl)
```

2. **判斷使用者有沒有說明 X 與 Y**：
   - 使用者已明確指出（例如「Y 是 count，X 是 age 和 sex」「以 outcome 為反應變數」）：照使用者說的做，並在列出變數後複述一次「反應變數：○○；解釋變數：△△、□□」讓使用者確認。
   - 使用者**沒有**說明（只丟資料、只說「幫我做 GLM／迴歸分析」）：**不要自己猜、不要直接開始分析**。列完變數表後，用 `AskUserQuestion` 以勾選框詢問（見「向使用者提問的方式」），把下面的問題集中在一次呼叫：
     1. 哪一個變數是**反應變數（Y，想被預測或解釋的結果）**？（單選，選項列出最可能的變數）
     2. 哪些變數**不要放進模型**（例如編號 ID、日期、重複資訊的欄位）？（多選，其餘變數視為解釋變數 X）
     
     選項可以根據變數名稱與型態給出「建議」（例如「`id` 看起來是編號，建議排除」「`count` 是非負整數，可能是反應變數」），但建議只是供選擇，仍必須等使用者回覆確認後才進行後續步驟。
   - 使用者只說了 Y 沒說 X：就只詢問 X（哪些要納入、哪些排除），反之亦然。
3. 如果有計數資料的暴露量（offset，例如觀察人年數、面積）或二元資料的分組試驗總數，也要在這一步（併入同一批勾選框）問清楚它是哪一個變數。
4. **確認時間順序（配適任何模型之前必做）**，這些問題也併入上面同一批勾選框：先讀 `references/model-building-and-validation.md` 的 A 節，然後
   - 研究目的固定為**解釋關聯**，**不需要再詢問研究目的**，也不要提供「建立預測模型」的選項。**本 skill 不做因果推論**：使用者想做因果推論時，要明講這個限制，只能描述關聯，因果推論請另用專門的方法。
   - 逐一檢查解釋變數。「記錄在結果之後」與「變數本身在結果之後才產生」並不相同，對可疑變數要分別釐清：**變數實際發生或存在的時間**、**被測量或記錄的時間**、**是否可能受到 Y 影響**，並對照研究目的。把這些列給使用者，詢問要排除還是保留，不要自行決定；預測則要看預測時點是否取得得到該變數；保留可疑變數時要在結論中交代可能的偏誤。
5. **最後一題：輸出形式**。其他問題都問完之後，在最後一批問題的最後加上輸出形式，**不要預設在對話裡分析**，讓使用者決定：「對話中逐步呈現」「Quarto 報告（PDF，預設格式）」「Quarto 報告（HTML）」。使用者在請求中已經明確指定（例如「幫我做成 PDF 報告」）就不用再問。選擇 Quarto 報告後，仍照 Stage 1-4 完整分析，只是結果寫進報告。
6. 使用者確認後，把確認結果寫成一段話（「研究目的：解釋關聯；反應變數：○○；解釋變數：△△、□□；排除：××；可能在結果之後才產生的變數：××」），後續所有階段都以這個設定為準。若之後發現設定有問題（例如 Y 其實不適合 GLM），回頭向使用者說明再討論，不要私自更改。

### Stage 1-1 以後：探索性資料分析

確認 X / Y 之後，至少做這些事，並逐項說明看到了什麼、代表什麼：

1. **資料結構**：`str(dat)` / `dplyr::glimpse(dat)`，確認每個欄位的型態（數值、因子、字元）是否符合預期。
2. **反應變數（Y）的分佈**：
   - 畫 histogram 或 bar chart（連續 vs 類別）
   - 印出 `summary(y)`；若是計數資料，順便算 `mean(y)` 和 `var(y)`，先初步感受一下有沒有 mean ≈ var（poisson 的假設）或 var >> mean（可能過度離散）。若用各組的變異數與平均數之比判斷，要考慮抽樣波動：在 Poisson 下，每組 n 筆的比值標準差約為 √(2/(n−1))（n = 12 時約 0.43；這是樣本獨立同分布 Poisson、用樣本變異數除以樣本平均數時的大樣本近似，不是所有資料情境都適用的精確公式），所以各組比值之間的差異不宜直接解讀成離散結構不同
3. **遺漏值**：`colSums(is.na(dat))`，報告各變數的缺失比例，說明可能的處理方式（刪除、插補，視情況建議）。**不得在未說明的情況下把缺失值當成 0 或用平均數填補**；使用完整個案分析要說明可能的偏誤；需要插補時要考慮缺失機制，並與使用者確認（細節見 `references/model-building-and-validation.md` 的 G 節）。配適模型後，還要報告模型實際使用的樣本數與因缺失被排除的筆數。
4. **解釋變數（X）與 Y 的關係**：連續 X 用散佈圖 + smooth line，類別 X 用 boxplot／分組長條圖，讓使用者先看到「大概的關係方向」。
5. **解釋變數彼此之間**：連續變數之間看相關係數矩陣（`cor()`），初步警覺潛在的共線性問題（正式檢定留到 Stage 4 用 VIF）。

這階段的產出是「對這筆資料的整體理解」，還沒有要做任何推論或配模型，語氣上要像是在幫使用者「認識資料」。

### Stage 1-2：資料檢查關卡（完整分析模式下，EDA 做完後的預設做法）

EDA 結果呈現完之後，**預設先停下來讓使用者確認資料有沒有問題**，不要自己判斷「看起來還好」就繼續。要特別把容易出現打字錯誤（typo）或奇怪數值的地方整理給使用者看：

1. **數值變數的最小值與最大值**：用一張表列出每個數值變數的最小值、最大值、平均、中位數，最大最小值要明顯可見。
2. **類別變數的所有類別與各類別個數**：用來抓拼字不一致（例如 `Male`／`male`／`M`）、多餘空白、不該出現的類別。
3. **分析流程要主動標出可疑之處**，並指出是哪個變數、哪個值：
   - 計數資料出現負數或小數
   - 二元變數出現 0／1 以外的值
   - 超出常理的值（例如年齡 200、比例大於 1、金額為負）
   - 離群很遠的極端值（例如超出 1.5 倍 IQR 很多）
   - 欄位型態與內容不符（例如數值欄位被讀成文字）
4. 表格與可疑項目呈現完後，直接問使用者：**「最大最小值和各類別有沒有看起來不對的地方？可能是打錯字、單位錯誤或奇怪的數值？」** 用 `AskUserQuestion` 提供「資料沒問題，繼續」「有問題，我來說明」兩個選項（勾選框），使用者選擇後再繼續。

使用者回覆後：
- **說資料沒問題**：直接進入 Stage 2。
- **指出有問題**：問清楚要怎麼處理（改成正確值、設為遺漏值、排除該筆觀測值），照使用者指示處理，不要自行決定。處理完後重新呈現受影響變數的最小值／最大值／類別，再確認一次，確認沒問題才進入 Stage 2。
- 如果沒有發現任何可疑之處，也要照樣呈現最小值與最大值並請使用者確認，因為只有使用者知道什麼數值在他們的情境中合理。

**這個關卡的例外**（避免一律卡住）：
- 發現可能的資料錯誤、異常編碼，或會改變模型結論的疑點時，**必須**停下來詢問，不能略過。
- 使用者明確要求教學示範、純探索性分析，或明確授權「資料沒問題，直接分析」時，可以繼續，但要在後續的結果與報告中**標示這些資料品質限制尚未由使用者確認**。
- 延續既有分析模式且資料沒有改變時，不必重複確認。

要產出報告檔案時，這張最大最小值表與可疑項目的說明也要放進報告的 EDA 章節。

## Stage 2：適合性評估——這筆資料適合 GLM 嗎？該選哪個 family / link？

先**確認資料結構**，再決定能不能直接套用一般 GLM：
- **相關觀測**：有沒有重複測量、同一個人／家庭／學校的多筆資料、群聚或巢狀結構？有的話，一般 GLM 的獨立性假設可能不成立，可能需要 GLMM、GEE 或其他方法，**這超出本 skill 的支援範圍**，要誠實告知並說明，不要假裝一般 GLM 已經處理好。
- **暴露量（offset）**：計數資料若各觀測的觀察時間、人年數、面積不同，要先確認是否需要 offset。
- **完全分離的跡象**：二元資料若某個變數幾乎完全決定 Y，要先辨識（見 `references/model-building-and-validation.md` 的 F 節）。
- **樣本數與事件數**：樣本數是否足夠要綜合判斷（事件比例、稀有事件、參數個數、資料分布與估計方法）；「每個參數 10–20 筆」只是粗略的經驗法則，不是准入標準，偏少時要明講估計可能不穩定。
- **極端值與資料輸入錯誤**：是否有需要先處理的問題。

接著依「反應變數的型態」決定**一個起始模型**（family 與 link）。詳細的判斷邏輯放在 `references/family-link-selection.md`，**進入這個階段時務必先讀取那份參考檔案**。依反應變數型態選 family/link 只是起始模型的起點，**不能僅憑 Y 的直方圖、偏態或整體平均數與變異數就宣稱分布假設成立**；要同時考慮研究問題、觀測值的獨立性、資料產生機制，以及解釋變數與 Y 的條件關係，並在配適後以診斷確認。若有多個同樣合理的 family 且資料無法分辨，向使用者說明，預設仍先配適一個，其餘等診斷結果或使用者要求再處理。

判斷完後，用一小段文字講清楚：「反應變數是 XX 型態 → 先以 YY 分佈、ZZ 連結函數配適，因為……，之後會用診斷確認」，讓使用者知道推理過程與這只是起點。

## Stage 3：模型配適

進入這階段時，先讀 `references/model-building-and-validation.md` 的 C 節。**預設只配適一個模型**，不要一開始就列出一堆候選模型（目的是避免盲目試模型再挑結果，不是硬性限制：研究問題本身就涉及要比較的結構、或有充分理論依據的幾個模型時，可事先說明理由並用勾選框問使用者要不要一起比較）；使用者明確要求比較多個模型（例如「幫我比較幾個模型」「看哪個預測變數組合最好」）時，才切換成候選模型比較（見下方「使用者要求比較多個模型時」）。依下列順序進行：

1. **決定這一個模型的設定**：family 與 link 依 Stage 2 的判斷；預測變數依 Stage 1-0 使用者確認的 X。**連續解釋變數一律以線性項放入模型，不在一開始配適二次方、多項式、樣條等非線性形式，也不做相關的函數形式檢定**（模型簡單、係數好解釋；要不要考慮非線性由後面的診斷結果決定，且只在報告中討論，不配適）。
2. 用 `glm(y ~ x1 + x2 + ..., family = 分佈家族(link = "連結函數"), data = dat)` 配適這個模型（稱為 m1）。**配適後立刻做估計是否成功的檢查**（收斂、完全分離、係數與標準誤是否極端、擬合機率是否貼近 0 或 1、實際使用的觀測數，見 `references/model-building-and-validation.md` 的 F 節）；能輸出 `summary()` 不代表估計可靠。
3. 之後由 Stage 4 的診斷決定要不要調整。**只有診斷出現證據顯示 m1 有問題時**（例如明顯過度離散、family 或 link 不合適），才提出調整後的第二個模型（m2），向使用者說明為什麼要調整，重新配適並重新診斷，再用概似比檢定（巢狀）或 AIC／BIC（相同分析樣本、可比較的概似模型）比較 m1 與 m2，這些比較要與殘差診斷、研究合理性分開看。**不要因為某個模型的係數比較容易解釋，就忽略明顯的配適不足**。沒有證據顯示有問題，就不需要其他模型。**殘差對某個連續變數呈現曲線時，不要自行加入非線性項重新配適**，而是在報告中如實描述，並說明「模型可能未捕捉非線性關係，後續可考慮改用非線性形式（例如樣條）」作為延伸討論；使用者明確要求時才配適。
4. 最終模型就是診斷後確認的那一個（沒有調整就是 m1）。報告不要寫出順序倒置的句子（例如先選定模型、再說「依後續診斷」）；若有調整，要依序說明「m1 → 診斷發現 → 調整為 m2 → 比較 → 確認」。

**使用者要求比較多個模型時**：列出候選模型並編號（m1、m2、…），在看結果之前先和使用者講好**選模原則**（巢狀用概似比檢定、非巢狀用 AIC／BIC、差距很小時選較簡單的、函數形式要合理）；所有候選模型必須使用相同的分析樣本（用 `nobs()` 確認）；quasi-family 不能用一般的 AIC 或標準概似比檢定；並排呈現觀測數、參數個數、收斂狀況、AIC、BIC、殘差偏差；提出「初步選定模型」與最有力的對手，Stage 4 對主要候選模型並排診斷後再確認最終模型。

5. 對最終模型印出 `summary(model)`（若 Stage 4 調整了模型，解釋要對最終模型重做），並且：
   - **逐一解釋每個係數**：注意 GLM 的係數是在 link scale 上，一般人看不懂，要轉換成好理解的量：
     - `logit` link → 用 `exp(coef)` 講成 odds ratio（勝算比）
     - `log` link（poisson / Gamma）→ 用 `exp(coef)` 講成 rate ratio 或倍數效果
     - `identity` link（gaussian）→ 係數本身就是原始尺度的效果，直接解釋
   - 可用 `broom::tidy(model, conf.int = TRUE, exponentiate = TRUE/FALSE)` 整理成表格，用 `knitr::kable()` 呈現（不要用 `kable_styling()`）。**`exponentiate = TRUE` 只轉換 estimate 與信賴區間，`std.error` 和 `statistic` 仍在 link scale**，表格只保留 `term`、`estimate`、`conf.low`、`conf.high`、`p.value`，或在標題註明；信賴區間的方法（profile 或 Wald）也要註明。
   - **類別變數有三個以上水準**時，若結論涉及非參照組之間的比較，或用了「最好」「最差」「排名」等措辭，必須用 `emmeans` 做兩兩比較並校正多重比較；沒做就只能說「點估計以某組最低」。
   - **「不顯著」不等於「相同」**：信賴區間包含 1（或 0）只能寫「資料無法區分」，不得寫成「效果相近」「沒有差異」。
   - 措辭一律用「關聯」，不用「導致」「處理效果」等因果語氣。
   - **解釋時必須交代**（細節見 `references/model-building-and-validation.md` 的 H 節）：類別變數的參照組、連續變數係數對應的增加單位、轉換後變數要依轉換後的尺度解釋（例如 `log1p(x)` 不能講成 x 增加 1 單位）、估計值盡量搭配信賴區間與 p 值、odds ratio 不是風險比也不能說成機率增加幾倍
   - 報告模型實際使用的樣本數，以及因缺失值被排除的筆數。
6. 講清楚整體模型的解釋力／適合度的初步指標（例如 `performance::r2(model)` 給出的 pseudo-R²），但強調這只是初步，真正判斷模型好壞要看 Stage 4 的診斷。

## Stage 4：模型診斷與評估

這階段是回頭檢查 Stage 2 選的 family/link 和 Stage 3 配的模型「站不站得住腳」。詳細的各家族診斷檢查清單、常見問題與對應補救方式放在 `references/diagnostics-checklist.md`，**進入這階段時務必先讀取那份參考檔案**，依裡面的項目逐一檢查，包含但不限於。**診斷先針對 m1 進行**（使用者要求比較多個模型時，對主要候選模型並排診斷），診斷完才正式確認最終模型：

- 殘差診斷（deviance / Pearson residuals 對 fitted values 作圖，**以及對每個重要連續解釋變數作圖**），找系統性結構與可能的非線性（只描述，不自動加入非線性項）；有時間、空間或群聚結構時另外檢查相依性。**GLM 不要求殘差服從常態，Q-Q 圖不能用來判定「誤差是否常態」**
- 過度離散檢查：依資料形式解讀，不把某個離散比值當成統一門檻；**單筆 0/1 的 binomial 沒有可獨立估計的額外離散參數**，不要據此換模型；quasi-family 不會修正錯誤的平均數結構、遺漏變數或相依性。**換成負二項後離散比值接近 1 並不意外，但不保證，也不能據此認定已充分配適，不是獨立驗證**；先確認各診斷函數實際用的統計量，若 `check_overdispersion()` 與手算 Pearson 檢定用同一統計量就不算兩份證據；θ 是估計的離散參數，`df.residual` 不會自動扣掉 θ 的數值，做 Pearson 卡方檢定時要確認所用方法的自由度如何處理 θ 的估計，不可把 `df.residual` 當通用的適合度檢定自由度。單筆二元資料雖沒有額外離散參數，仍要檢查平均數結構、相依性、校準與分離問題。裝得到 DHARMa 時可用模擬殘差補充
- 共線性（`car::vif()`）：VIF 是警示不是自動刪除變數的規則；含因子或多自由度項時要看 GVIF 的調整值
- 計數資料的零值：比較實際與預期的 0 個數，評估差異的大小與不確定性，**不用固定百分比當門檻**。零值偏多不等於零膨脹，**先評估過度離散、平均數結構、遺漏變數、觀測相依等替代解釋**；仍無法合理解釋時，才說明零膨脹與門檻模型（機制不同，不能視為同一種）的區別，並告知**本 skill 不支援這兩種模型的配適**，請使用者另行處理
- 適合度檢定：確認該檢定的資料結構與近似條件成立，條件不足時只當有限的診斷證據；單筆二元資料不把 Pearson 或 deviance 卡方當標準檢定，改看校準與預測評估
- 用 base R 的 `plot(model)`（`par(mfrow=c(2,2))` 四合一）當總覽圖（R 對 GLM 用 `plot.lm()` 的方法，不保證產生這四張圖，要先確認實際產生哪些），存成圖檔展示給使用者。這張圖不能取代依 family 選擇的診斷，四張圖也不適用同一套判讀標準（不要預設用 `performance::check_model()` 的畫圖功能，因為它依賴的 `see` 套件在此環境不一定裝得到）

**診斷完成紀錄**：Stage 4 結束前列一張表，記錄每項檢查是「已執行且可判讀」「已執行但結果受限」「不適用而跳過」或「無法執行」，並寫明原因（細節見 `diagnostics-checklist.md`）。不要只說「已讀取診斷清單」就假設每項都做了，也不要把「沒發現問題」「不適用」「沒執行」混為一談。

**診斷通過不等於預測能力良好**：本 skill 的目的是解釋關聯，**預設不做樣本外預測評估（交叉驗證）**。結論中要明講這一點；需要說明整體配適程度時，報告樣本內的指標（pseudo-R² 等）並註明是樣本內、通常偏樂觀。使用者主動要求驗證預測表現時才做交叉驗證（做法見 `references/model-building-and-validation.md` 的 D 節）。

**分析與輸出（對話或 Quarto 報告）完成後**，在交付結果時，用一句話提醒使用者：若要用最終模型預測新資料，可以直接提供新資料（不用勾選框詢問，也不用等回覆；使用者已提出就不用再提醒）。使用者提供新資料時，直接用最終模型 `predict(model, newdata)`，不需要重新切分、重新訓練，並說明三件事：(1) 預測表現沒有經過驗證，診斷通過不等於預測能力良好；(2) 新資料的變數範圍與來源要與原樣本相近，超出範圍或來自不同群體、時間是外推，預測不可靠；(3) 新資料有真實的 Y 時，可以直接計算預測誤差來確認。

每一項檢查都要明講「這個檢查在看什麼、結果怎樣、可能的原因與處理選項」，並依「統計判斷與自動化決策原則」把診斷當作證據，不是自動決策規則。如果診斷發現問題嚴重到動搖 Stage 2/3 的結論，要明確告知使用者，並視情況回頭調整模型、重新配適並重新診斷，而不是隱瞞問題硬給一個「看起來很正式」的結論。

### Stage 4-1：結論要和最終模型一致

撰寫結論時遵守上面的「結果與結論撰寫原則」。

寫總結之前，先讀 `references/model-building-and-validation.md` 的 E 節：

- 明確寫出最終模型是哪一個（Stage 4 診斷後確認的那一個，若有調整就不是 m1），結論中所有估計值、診斷結果，**都必須來自最終模型**。類別變數或多自由度項的整體檢定也要用最終模型重做，不得沿用候選模型（如 Poisson、quasipoisson）的檢定結果。
- 若選了較複雜的模型（例如 m4），就以 m4 的估計為主要結論；若保留較簡單的模型（例如 m2），要清楚說明簡化的目的與配適限制（例如概似比檢定顯示 m4 顯著較佳）。
- **不要混用不同模型的結果而不交代**；引用其他模型的數字時，要標明是哪個模型、為什麼引用。
- **寫完結論後逐句檢核**：(1) 每個數字是否來自最終模型？(2) 每個比較性陳述（較好、最佳、相近）是否有對應的檢定支持（多重比較校正）？(3) 有沒有出現因果措辭（本 skill 只描述關聯）？(4)「不顯著」有沒有被寫成「相同」？(5) 整體檢定是否來自最終模型？不通過的句子要改寫。

## 輸出形式：對話中呈現 vs 產出報告檔案

**沒有預設值**：不要自動在對話裡分析。輸出形式由使用者在 Stage 1-0 最後一題決定（使用者在請求中已指定就照做）。兩種都要能做：

- **對話中呈現**：每個階段的 R 程式碼只在背景執行（用環境可用的 R 執行工具），**回覆中不要貼 R 程式碼**，除非使用者明確要求看程式碼。回覆只呈現執行結果（整理成易讀的表格與數字）、圖檔（用環境提供的方式展示）以及對結果的白話解釋，依 Stage 1-4 的順序分節說明。使用者沒有要求就不要主動提供程式碼，也不要說「程式碼如下」。
- **產出報告檔案**（使用者要 PDF / HTML 報告時；選 Quarto 報告又沒指定格式，預設輸出 PDF）：用 `assets/report_template.qmd` 當骨架複製一份出來修改（這是使用者習慣的 Quarto 範本，一份檔案同時支援 pdf、html 兩種輸出），內容依 Stage 1-4 填入對應的程式碼與文字說明，再用 `LC_ALL=C.UTF-8 quarto render report.qmd --to pdf`（或 `html`）轉出。圖表要用 `#| label: fig-xxx` / `tbl-xxx` 搭配 `#| fig-cap:` / `#| tbl-cap:` 寫標題，內文用 `@fig-xxx` 交叉引用，章節標題用 `#`（編號由 `number-sections` 自動產生）。使用者只要其中一種格式時，把 YAML 裡其他 format 區塊刪掉。轉出的檔案放到目前環境實際支援的輸出位置，並用環境提供的檔案傳送方式交給使用者。**預設交付時，除了轉出的 PDF 或 HTML 之外，一律同時附上最終的 `.qmd` 原始檔**（可重現、可自行修改），使用者明確說不要才省略。交付的 `.qmd` 必須就是實際用來轉出報告的那一份，並附上資料檔路徑或說明。若使用者只說「報告」沒指定格式，輸出 PDF。PDF 報告要顯示程式碼（`echo: true`），HTML 報告的程式碼預設摺疊（`code-fold: true`），這兩項是範本的預設，不要關掉。不輸出 Word。範本內的字型設定、YAML 結構不要隨意更動，這是使用者自己的版面偏好。

**轉出報告後必須實際檢查成品**：PDF 要用環境的工具把頁面轉成圖片或讀出文字，逐頁確認：(1) 希臘字母與數學符號是否正常顯示（內文的數學符號一律用 `$\mu$` 這類 LaTeX 寫法，不要直接打 Unicode 符號，否則可能漏字或變成亂碼）；(2) 表格有沒有重複的列名欄（`data.frame` 一律加 `row.names = NULL`）；(3) 圖表有沒有缺字或方框。HTML 也要確認能開啟、程式碼可摺疊且表格、圖正常。發現問題就修正後重新轉出，不要把沒檢查過的檔案交給使用者。

完整分析模式下，不論哪種輸出形式，都必須完整走過 Stage 1-4，不能因為要產出報告檔案就把逐步解釋省略掉、只留下結果表格。報告中的所有數字都要對應到最終模型。
